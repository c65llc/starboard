# Starboard Plan 4 — Examples and the website — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish `starboard.c65llc.com`, a detailed marketing and documentation site with a blog, built like coding-standards' site. Every image and example comes from Starboard's own output, the rule reference is generated from the binary, and the PWA is served at `/app`.

**Architecture:**
- Two complete example projects in `examples/` are linted and generated in CI by the freshly built binary.
- A new `starboard rules` command exports rule metadata. Diagnostics gain a `docs` URL.
- The site, under `website/`, is Astro + Starlight + starlight-blog. A prebuild script copies the docs, generated rule pages, example output, JSON Schemas and the PWA build into it.
- Cloudflare Pages deploys a `live` branch that a publish workflow fast-forwards only on a release or a blog-post change, exactly as coding-standards does.

**Tech Stack:**
- Astro, `@astrojs/starlight`, `starlight-blog`, `@astrojs/rss` and `sharp`. Use the same major versions as coding-standards' `website/package.json` on its `main`, at the newest patch at least 3 days old.
- Node 24 and pnpm.

**Spec:** `docs/specs/2026-11-26-starboard-design.md`, sections Marketing site, Repository layout, `examples/`, and the domain decision (`starboard.c65llc.com`, PWA at `/app`).

**Depends on:**
- Plans 1 and 3, for the CLI and skills docs.
- Plan 2, for `/app`. If Plan 2 isn't merged, Task 4 ships without `/app` and adds it in a follow-up.

**Delivery:** Two PRs:

- **PR 1:** Tasks 1–2, the examples and `starboard rules`
- **PR 2:** Tasks 3–5, the website and publishing

Then the human steps in Task 5.

## Global Constraints

- Plans 1–3's Global Constraints still apply.
- **pnpm per directory:** corepack pins pnpm per directory, from the `packageManager` field of the nearest `package.json`, so pnpm always runs from inside the package (`cd <dir> && pnpm …`), never as `pnpm -C <dir> …` from elsewhere.
- **The site has no tracking:** no analytics, no third-party scripts, and self-hosted fonts.
- **CSP:** copy coding-standards' `website/scripts/csp-postbuild.mjs` approach and `inlineStylesheets: 'never'`. `/app/*` additionally allows `'wasm-unsafe-eval'` and `worker-src 'self'`, set in a Cloudflare Pages `_headers` file.
- **JSON Schemas resolve:** `https://starboard.c65llc.com/schema/v1/config.json` and `/screens.json` serve exactly the files embedded in the binary, because their `$id` URLs point there.
- **Content is accurate:** every CLI example on the site is a testscript-verified command or copied from one. Content is never generated by hand, and there is no lorem ipsum.
- **Accessibility:** WCAG 2.2 AA. The landing page and one docs page pass axe in CI.

## Review Focus

1. **The docs and the binary drift apart.** A rule with no page, a page for a removed rule, or a schema URL that doesn't match the embedded file all fail CI. Covered by `TestRuleDocsComplete` and `site-check.mjs`.
2. **The example projects stop linting** after a format or rule change. CI runs `starboard lint` on every example and fails. Covered by `make examples-check`.
3. **The PWA's service worker scope** escapes `/app/` and caches the marketing site, or a stale app outlives a release. The scope must be `/app/`, and the update toast shows after a deploy. Covered by Playwright `site-app.spec.ts` against the built site.
4. **Publishing on every merge.** Only releases and blog-post changes move `live`. Covered by `publish.yml`'s `on:` filters, which are reviewed against coding-standards' workflow.
5. **Broken internal links and images** across synced content. Covered by an `astro-link-check`-style script (`scripts/check-links.mjs`) over the built `dist/`, run in CI.

- Test: `internal/lint/docs_test.go`, `cmd/starboard/testdata/script/rules.txtar`

**Interfaces:**
- `Rule` gains `Summary string`, a one sentence description.
- `Diagnostic` gains `Docs string` (JSON `docs,omitempty`), set to `https://starboard.c65llc.com/rules/<id>/`.
- `starboard rules [--json]` prints every rule's ID, kind (`correctness`/`quality`), default severity and summary. The JSON form is `{"version":1,"rules":[{"id","kind","default","summary","docs"}]}`, sorted.
- **Each `docs/rules/<id>.md`** has front matter `title: <id>` and `description: <summary>`, and the sections `What it catches`, `Why it matters`, `How to fix`, `Example` (a failing YAML snippet and the fixed one) and `Configuration` (quality rules only).
